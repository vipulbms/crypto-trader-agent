# Session Notes — 6 April 2026 (Part B)

## Changes

### 1. Fix GitHub Sub-Issues API call in `create_story()`

**Bug report / Feature request:** The `create_story()` function in `scripts/create_github_issues.sh` failed to link Stories as Sub-Issues of their parent Epics when the script was run. Each story was created standalone with the message `(sub-issue API unavailable — story #N created standalone)`.

**Root cause:** The `gh api` call was missing two required HTTP headers (`Accept: application/vnd.github+json` and `X-GitHub-Api-Version: 2026-03-10`) and used `--field` instead of `-F` for the POST body parameter, causing the GitHub Sub-Issues API to reject the request silently.

**Fix / Implementation:**
- Updated `scripts/create_github_issues.sh` lines 26-31: replaced broken `--field sub_issue_id=...` with the correct headers and `-F "sub_issue_id=..."` form.

---

### 2. Create `scripts/link_epics.sh` — Retroactive Sub-Issue Linker

**Bug report / Feature request:** The 45 Stories already created during the previous run were left as standalone issues (not linked to their parent Epics). A retroactive linker was needed to fix this without re-creating any issues.

**Root cause / Motivation:** The original script created all 45 stories but linking silently failed. Rather than re-running the 400-line creation script, a targeted script that discovers existing issues by label and POSTs to the Sub-Issues API was needed.

**Fix / Implementation:**
- Created `scripts/link_epics.sh` — iterates `E1..E12`; for each, discovers the Epic's issue number (`label: epic,E{N}`) and all Story issue numbers (`label: story,E{N}`) via `gh issue list --json number --jq`; then POSTs each story as a sub-issue of the epic using the correct Sub-Issues API headers.
- Script is idempotent — already-linked stories produce a non-fatal error message and continue.
