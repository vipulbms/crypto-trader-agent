# Session Notes — 5 April 2026 (Part D)

## Changes

### 1. Execution Optimization: Post-Only & Taker Fee Mitigation

**Bug report / Feature request:** Implement Limit Order with Chase Logic.

**Root cause / Motivation:** Market orders incur ~0.26% Taker fees. Limit orders ensure Maker fees (~0.16% or less), saving significant capital over time.

**Fix / Implementation:**
- Updated `src/exchange/kraken_client.py` and `src/exchange/paper_broker.py` to use limit orders with `postOnly: True` parameters for entries.
- Added chase logic: replacing stale unfilled limit orders after 60 seconds with new best bid limit orders.

### 2. Strategy Enhancement: Time-of-Day Filter & Volume Guard

**Bug report / Feature request:** Implement Volatility Windows.

**Root cause / Motivation:** Trading during low-volume "dead zones" leads to false breakouts and wicks out stop losses. Only trade when volume supports momentum.

**Fix / Implementation:**
- Configured accepted window between 16:00 and 20:00 UTC in `config.yaml`.
- Enforced Time-of-Day bounds during entry evaluation in `src/risk/risk_manager.py`.
- Added 20-period Volume SMA indicator to `src/analysis/indicators.py`.
- Enforced a hard 50% dead-zone volume guard inside `src/analysis/signals.py`, blocking trades if current volume is lower than the allowed threshold against moving average.
- Recorded constraints in `.claude/skills/trading-rules/SKILL.md`.
- Added unit tests in `tests/test_risk_manager.py`.

### 3. Architectural Resilience: Heartbeat & Health Check Webhook

**Bug report / Feature request:** Implement a Health-Check Webhook to alert if the bot process hangs silently.

**Root cause / Motivation:** The bot may hang due to DNS errors or system freezes without throwing exceptions to catch blocks. 

**Fix / Implementation:**
- Created a `ping_healthcheck` method in `src/notifications/notifier.py`.
- Hooked up `healthcheck_url` parameter in `config.yaml` to invoke webhook at the completion of every `main.py` cycle unconditionally.
