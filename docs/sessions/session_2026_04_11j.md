# Session Notes — 2026-04-11 (Part J)

## Changes

### 1. Fix: cash guards as primary gate, count ceiling raised to 10 (#167)

**Bug report / Feature request:**
GH #167 — `max_open_positions` count gate was stranding cash when caution-factor positions
were small. 5 slots exhausted at ~$376 deployed with $624 idle.

**Root cause / Motivation:**
`max_open_positions: 5` was derived in #159 assuming every position consumes the full
`base_position_pct: 16%` of portfolio. `caution_factor_bearish` (e.g. SUI=0.35) reduces
actual sizes to $35–$70, filling 5 count slots while leaving hundreds of dollars untouched.
The #165 partial fix (soft gate — block only when count≥max AND deployable < min_order_usd)
was correct in direction but wrong in architecture: the count gate was still the primary
control; cash guards were secondary.

**Fix / Implementation:**

`config.yaml`:
- `max_open_positions: 5` → `10` — raised to a safety ceiling that is unreachable in normal
  operation on a $1,000 portfolio (`10 × $20 min = $200`; cash depletes long before 10 slots).
  Comment updated to explain it is a safety net, not primary control.

`src/risk/risk_manager.py` — `validate_buy()` guard reorder:
- Moved "3. Min cash reserve" and "Guard 0.5 deployable < min_order_usd" to run **before** the
  count ceiling check. This makes cash exhaustion the primary gate (most common blocker).
- Restored count gate to a simple unconditional hard block (removed the #165 dual-condition
  soft peek). Fires at 10 — safety net only.
- New guard order after daily-loss check:
  1. Min cash reserve (was step 3 → now first cash check)
  2. Guard 0.5: deployable < min_order_usd (moved up)
  3. Count ceiling at 10 (hard, unconditional)
  4. Correlation cluster guard (unchanged)
  5. Remaining size guards (Guard 1, flash crash, fat finger, 98% buffer, cap)

`src/risk/risk_manager.py` — `validate_config()` sanity warning:
- Changed from `config.get("position_sizing", {}).get("base_position_pct", 16)` to
  `config.get("trading", {}).get("max_position_pct", 20)`. The formula now checks
  `max_open_positions × max_position_pct > max_deployable`, consistent with the primary
  sizing parameter used in `main.py`.

`tests/test_risk_manager.py`:
- `test_max_open_positions_blocked_when_no_cash`: updated — same low-cash scenario now
  blocks via Guard 0.5 (reason "Deployable cash …") not the count gate.
- `test_max_open_positions_allowed_when_cash_available`: updated `max_open_positions` to 10
  and docstring to reflect new architecture.
- New: `test_max_open_positions_ceiling_hard_blocks_at_10` — count=10 with plenty of cash
  → blocked unconditionally at ceiling.

`tests/test_position_sizing_floor.py`:
- Added `"max_position_pct": base_position_pct` to `trading` dict in `_full_config()` helper
  so all 4 sanity-warning tests continue to use consistent values.
- Updated docstrings to reference `max_position_pct` per #167.

**Result:** 183/183 tests pass. Cash is now the primary blocker; the count ceiling is a
last-resort safety net that fires only in edge cases.
