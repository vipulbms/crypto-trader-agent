# Session Notes — 2026-03-31 (Part E)

## Changes

### 1. Two Safety Nets Added to `_run_cycle_decision()`

#### Safety Net 1 — Zero Tool Calls (Silent Inaction)
If the LLM returns zero tool calls, the entire cycle would silently hold all pairs with no indication of failure.

**Fix** (`src/agent/trading_agent.py`):
- After the LLM call, if `tool_calls_made` is empty: log a `WARNING` showing how many pairs were held and how many BUY signals were missed
- Also writes an `audit.log_error("agent", "ZeroToolCalls", ...)` entry so it's visible in the audit DB

#### Safety Net 2 — Signal Mismatch (LLM Buys Against Signal)
LLM could propose `propose_buy` for a pair whose computed signal is not BUY (e.g. HOLD or SELL), ignoring the signal data.

**Fix** (`src/agent/trading_agent.py`):
- After `_resolve_pair()` succeeds, check `signal_by_pair[matched_pair]` against the tool called
- If `propose_buy` is called on a non-BUY signal pair: log WARNING, decrement `buy_count`, skip
- `signal_by_pair` dict is built once from the signals list before the tool call loop

**Note on pre-existing minor issue (not introduced this session):**
If the hallucination guard (`_resolve_pair`) skips a `propose_buy`, `buy_count` was already incremented but is not decremented — that slot is consumed. This was pre-existing. Safety net 2 correctly decrements because by that point the pair is validated.
