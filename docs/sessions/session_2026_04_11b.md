# Session Notes — 2026-04-11 (Part b)

## Changes

### 1. OBV Accumulation Signal (#136)

**Feature request:** Add On-Balance Volume trend to buy scoring to detect whether smart money is accumulating or distributing.

**Motivation:** The system only checked volume *level* (Hard Blocker 3 — dead zone). It ignored volume *direction*. OBV rising while price consolidates is a reliable precursor to breakouts; OBV falling while holding is a distribution warning.

**Implementation:**
- `src/analysis/indicators.py`: Compute full OBV series (`direction × volume`, cumulative). Return last 30 values as `obv_series` in the indicator dict.
- `src/analysis/signals.py`: Added `_compute_obv_trend(obv_series, period)` helper — compares OBV[now] vs OBV[now - period] with a 0.1% noise threshold. OBV rising → +1 BUY (`obv_accumulation_weight`). OBV falling → distribution warning added to reasons (no score penalty). OBV flat → no effect.
- Per-pair `obv_trend_period` override in `trading.pairs[]` (same pattern as `rsi_divergence_lookback`). Global fallback: `indicators.obv_trend_period: 10`.
- Estimation table in add-pair skill: BTC/LTC=14 (slow), ETH-tier=10 (mid), DOGE/HYPE=7 (fast/meme).
- `config.yaml`: `obv_trend_period: 10`, `obv_accumulation_weight: 1`.

### 2. BB Squeeze Release Detection (#137)

**Feature request:** Reward the candle where BB width expands sharply after a compression period (the "squeeze release" — one of the highest-probability breakout setups).

**Motivation:** The system already blocked trades *during* BB squeeze (Hard Blocker — width < threshold). But it did not reward the *release* from squeeze, missing the best entry candle of the setup.

**Implementation:**
- `src/analysis/indicators.py`: Compute `bb_width_series` (BB width as % of price, last 10 values). Return in indicator dict. Added standalone `detect_bb_squeeze_release(bb_width_series, threshold, lookback, expansion_factor, bb_mid, price)` — all three conditions must hold: (1) prior `lookback` candles all in squeeze, (2) current width > threshold × expansion_factor, (3) price > bb_mid (upward only).
- `src/analysis/signals.py`: Calls `detect_bb_squeeze_release` using per-pair `bb_squeeze_threshold_pct` (already in config). Awards +2 BUY (`bb_squeeze_release_weight`) on release. Downward breaks (price < midband) are explicitly rejected.
- `config.yaml`: `bb_squeeze_release_weight: 2`, `bb_squeeze_release_expansion_factor: 1.2`, `bb_squeeze_release_lookback: 3`.
- `max_score` updated: 22 → 25 (+1 OBV, +2 BB release).
