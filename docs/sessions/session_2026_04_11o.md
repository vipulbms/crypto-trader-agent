# Session Notes — 2026-04-11 (Part O)

## Changes

### 1. Fix: qwen3-32b thinking mode safeguards (#177)

**Bug report:** qwen/qwen3-32b on Groq supports a "thinking" (chain-of-thought) mode
that emits `<think>…</think>` blocks before its response. Unlike Ollama (which strips
these before populating `msg.tool_calls`), the Groq OpenAI-compat API may return thinking
content mixed into the response payload, causing zero tool calls and silent all-HOLD cycles.

**Root cause:** `_call_openai_compat` in `src/agent/trading_agent.py` did not (a) suppress
thinking mode or (b) strip `<think>` blocks from `msg.content`.

**Fix / Implementation:**

Two-layer defence introduced:

- **Option A (prevention):** Added `disable_thinking: bool` config flag
  (`llm.disable_thinking`). When `True`, passes `extra_body={"thinking": {"type": "disabled"}}`
  to the Groq API call, suppressing thinking mode at source. Set to `true` in `config.yaml`
  for the active `qwen/qwen3-32b` Groq config.

- **Option B (defence-in-depth):** `re.sub(r"<think>.*?</think>", ...)` is always applied
  to `raw_output` in `_call_openai_compat`, regardless of the flag. This is a no-op for
  models without thinking mode.

**Files changed:**
- `src/agent/trading_agent.py` — added `import re`; `_disable_thinking` attribute; updated
  `_call_openai_compat` to accept `extra_body` kwarg + strip think blocks from `raw_output`
- `config.yaml` — added `disable_thinking: true` to active Groq/qwen3-32b LLM config
- `tests/test_trading_agent.py` — new test file; 7 tests across `TestThinkBlockStripping`
  and `TestDisableThinking` classes

**Test results:** 190/190 tests pass.
