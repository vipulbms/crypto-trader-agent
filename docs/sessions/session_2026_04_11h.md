## Changes

### 1. Add `scripts/reset_paper.py` — paper trading clean-slate reset utility

**Bug report / Feature request:** Resetting paper trading state previously required manual SQLite commands (as done in session_2026_04_10b and session_2026_04_11g). A scripted, repeatable reset avoids errors and makes fresh test runs trivially easy.

**Root cause / Motivation:** No tooling existed for resetting the paper trading databases. Developers had to remember exact table names, FK deletion order, and re-seed syntax.

**Fix / Implementation:**

New script: `scripts/reset_paper.py`

- **What it clears:**
  - `paper_trading.db`: `paper_wallet`, `paper_positions`, `paper_trades`, `agent_state`
  - `audit.db`: all rows where `mode = 'paper'` across all 9 audit tables, respecting FK deletion order (fills → position_events → orders → risk_checks → llm_decisions → signals → cycles → balance_snapshots → errors). Live rows (`mode='live'`) are untouched.
- **Introspection:** Before acting, prints current state (cash balance, open positions, closed positions, trades, audit cycle count, balance snapshot count).
- **Confirmation prompt:** Interactive `[y/N]` unless `--yes` flag is passed.
- **Re-seed:** Inserts a fresh `paper_wallet` row with the specified `--balance` (default $1,000.00).
- **Post-reset verification:** Asserts cash == balance, 0 positions, 0 trades, 0 audit cycles, 0 balance snapshots before reporting success.

**Usage:**
```bash
python scripts/reset_paper.py                    # interactive confirmation
python scripts/reset_paper.py --yes              # skip prompt
python scripts/reset_paper.py --balance 500 --yes
```
