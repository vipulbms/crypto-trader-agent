# Session Notes — 2026-04-11 (Part C)

## Changes

### 1. Shorten adaptive floor lookback 400→200 candles (#141)

**Feature request:** `adaptive_atr_floor_lookback` was 400 candles (100h at 15min bars), lagging behind regime shifts by ~4 days.

**Root cause / Motivation:** 400 candles on a 15-minute chart covers ~4.2 days of history. During fast-moving markets (post-news, halving, macro shocks), the ATR floor, BB squeeze threshold, and volume floor adapt slowly — blocking valid entries or passing risky ones.

**Fix / Implementation:** `config.yaml` — all 14 per-pair `adaptive_atr_floor_lookback: 400 → 200`. Global defaults: `adaptive_atr_floor.lookback_candles`, `adaptive_bb_squeeze.lookback_candles`, `adaptive_volume_floor.lookback_candles` all changed to 200. BTC comment updated to "50h rolling window".

---

### 2. Enable partial take-profit (#142)

**Feature request:** `partial_take_profit.enabled` was `false` — the feature was implemented in #87 but never backtested or enabled.

**Root cause / Motivation:** The partial TP code is fully tested (51 tests). Enabling it locks in 50% profit at 50% of TP distance, moves SL to breakeven on remainder — eliminating the worst-case loss on the back half of every trade.

**Fix / Implementation:** `config.yaml` — `partial_take_profit.enabled: false → true`. Comment updated to note it's now enabled.

---

### 3. Correlation guard in validate_buy() (#139)

**Feature request:** No guard against stacking highly-correlated pairs (BTC/ETH/BNB/SOL all open = 4× BTC exposure). During corrections, all four hit SL simultaneously.

**Root cause / Motivation:** The risk manager treats each pair independently. BTC/ETH/BNB/SOL have ~0.85 rolling correlation — holding all four is concentrated risk.

**Fix / Implementation:**
- `config.yaml`: Added `correlation_clusters` list under `risk:` (4 clusters: large_cap_l1, memecoins, alt_l1, payment_legacy), `max_cluster_positions: 2`, `cluster_size_penalty: 0.5`.
- `src/risk/risk_manager.py`:
  - `__init__`: parses `correlation_clusters`, `max_cluster_positions`, `cluster_size_penalty` from config
  - `_get_correlation_cluster(pair)`: returns cluster dict `{name, pairs}` for a pair or None
  - `_get_open_pairs()`: queries DB for currently open pair names (same pattern as circuit breaker)
  - `validate_buy()` Guard 2a (after max-positions, before min-cash): if cluster already has ≥ `max_cluster_positions` open → REJECT; if cluster has 1 open → apply `cluster_size_penalty` (50% size reduction)
- `tests/test_correlation_guard.py` (new): 3 tests — penalty on 2nd position, block on 3rd, no penalty for different cluster

### 4. Graduated circuit breaker — exponential backoff (#143)

**Feature request:** Fixed 4h pause is too aggressive on first trigger (misses recovery) and too lenient on repeat triggers (no learning).

**Root cause / Motivation:** 3 stops on a volatile day early in a session → 4h miss recovery. Repeated daily triggers signal systematic problems needing progressively longer pauses.

**Fix / Implementation:**
- `config.yaml`: Added `pause_tiers_hours: [1, 2, 4]` and `tier_reset_hours: 24` to `circuit_breaker`. Kept `pause_hours: 4` for backward compat.
- `src/risk/risk_manager.py`:
  - `__init__`: reads `pause_tiers_hours` → `_cb_pause_tiers = [h*3600]`; falls back to `[pause_hours*3600]*3` for backward compat. `_cb_pause_secs = max(tiers)` (kept for logging).
  - `_count_circuit_fires_in_window(hours)`: queries `tier_reset_hours` of trade history, walks in ASC order counting complete N-stop streaks.
  - `is_circuit_open()`: fires tier lookup (`tier_idx = fires - 1` clamped to `len(tiers)-1`), derive `pause_secs` for window check and `resume_in` computation. **Bug fixed**: `resume_in` now uses local `pause_secs` not `self._cb_pause_secs`.
- `tests/test_circuit_breaker.py`: 3 new graduated tests using `test_paper_cb_graduated.db` (isolated from production data to avoid 24h fire count contamination).
