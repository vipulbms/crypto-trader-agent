### 2. Per-pair caution_factor_bearish — Fix #124

**Feature request:** In bearish regime, the global 0.5 caution halves position size for all pairs regardless of individual performance. Profitable pairs (ETH/BNB/DOGE) should not be penalised; underperformers should be cut harder.

**Calibration methodology:** For each pair, identified all bearish windows (price < 200-SMA) from `/history/*.json` candles. Computed peak-to-trough drawdown per window, took median. Mapped median drawdown to caution factor (higher drawdown → lower factor). Adjusted −0.1 across the board per user request. Winners (ETH/BNB/DOGE) set to 1.0 (buy the dip).

**Final per-pair values:**
| Pair | caution_factor_bearish |
|---|---|
| ETH/BNB/DOGE | 1.0 |
| BTC/LTC/TRX/XRP | 0.8 |
| ADA/AVAX | 0.6 |
| SOL | 0.6 |
| UNI/INJ (global default) | 0.5 / 0.35 |
| SUI/INJ | 0.35 |
| RAILS/HYPE | 0.4 |

**Implementation:**
- `config.yaml`: `caution_factor_bearish` field added per pair in `trading.pairs[]`
- `main.py` lines 535–558: replaced single global caution application with per-pair loop. In bearish regime, injects `sig["pair_max_usd"]` per signal. Volatile regime retains global caution_factor applied uniformly.
- `src/agent/prompts.py`: per-pair block now shows `Max buy size: $X (regime-adjusted)` when `pair_max_usd` is set. Fixed stale "30%" comment to "20%".
