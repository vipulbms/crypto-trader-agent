## Changes

### 1. Profit Factor Auto-Escalation (#183)

**Feature request:** Automatically raise `buy_min_score` for pairs whose rolling 30-day profit factor is below 1.0, making the agent more selective on historically poor performers without requiring manual config edits.

**Motivation:** Some pairs (e.g. INJ, SUI post-correction) accumulate a string of stop-losses that drag PF below 1.0 — meaning losses outweigh wins. Continuing to enter them at the standard minimum score compounds losses. Raising the threshold dynamically reflects real-world underperformance without permanently blacklisting a pair.

**Implementation:**

- **`config.yaml`** — Added `signals.profit_factor_escalation` block after `sell_min_score`:
  ```yaml
  profit_factor_escalation:
    enabled: true
    lookback_days: 30
    min_trades: 10           # Minimum closed trades required before escalation kicks in
    pf_warn_threshold: 1.0   # PF < 1.0 → raise buy_min_score +1
    pf_severe_threshold: 0.7 # PF < 0.7 → raise buy_min_score +2
  ```

- **`src/analysis/features.py`**:
  - Added `compute_profit_factor(pair, trades) -> Optional[float]` before `build_ai_context()`
  - Returns `None` when `len(trades) < 10` (insufficient history — no escalation)
  - Returns `float("inf")` when no losses exist (all wins)
  - Otherwise `round(gross_wins / gross_losses, 2)`, logged at DEBUG

- **`src/analysis/signals.py`**:
  - Added PF escalation block in `generate_signal()` after `reasons = []` initialisation, before scoring begins
  - PF < `pf_severe_threshold` (0.7): `buy_min_score += 2`, reason appended
  - PF < `pf_warn_threshold` (1.0): `buy_min_score += 1`, reason appended
  - No escalation when PF ≥ 1.0, None, or config disabled

- **`main.py`**:
  - Added `from datetime import datetime, timezone, timedelta` (added `timedelta`)
  - In `for pair in pairs` loop: DB query last 30-day closed trades for each pair, calls `compute_profit_factor()`, injects `indicators["profit_factor"]` before `generate_signal()` is called
  - Wrapped in try/except — failures silently skip injection (agent continues normally)

- **`src/cli/display.py`**:
  - `print_portfolio_summary()`: open positions now print `PF:X.XX` inline (red < 0.7, yellow < 1.0, dim if healthy); reads from `data.get("profit_factors", {})`
  - Added `print_profit_factor_table(pf_data: dict)` — Rich table with Pair / Profit Factor / Trades / Status columns, colour-coded rows

- **`src/reports/trade_report.py`**:
  - Added `get_profit_factors(mode, config, days=30) -> dict` — queries last 30-day closed trades, groups by pair, calls `compute_profit_factor()` per pair
  - Returns `{pair: (pf_value_or_None, n_trades)}`; pairs with < `min_trades` return `(None, n)`
  - `get_portfolio_summary()` now includes `"profit_factors": get_profit_factors(mode, config)` in its return dict

- **`src/cli/commands.py`**:
  - `cmd_report()`: after `print_portfolio_summary()`, also calls `d.print_profit_factor_table(rpt.get_profit_factors(mode, config))`

- **`tests/test_profit_factor.py`** (new) — 10 tests:
  - `compute_profit_factor`: severe (< 0.7), warn (0.7–1.0), healthy (≥ 1.0), insufficient trades (None), no-loss (inf)
  - `generate_signal` integration: PF=0.65 raises score by 2, PF=0.85 raises by 1, PF=1.5 no change, no PF injected no change, disabled config no escalation
