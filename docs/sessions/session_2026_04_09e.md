# Session Notes — 2026-04-09 (Part E)

## Changes

### 1. Fix trailing stop exits mislabelled as `stop_loss` (GH#123)

**Bug report:** In the 2026-04-09 backtest, 60 of 84 exits were labelled `stop_loss`, but many were profitable trailing-stop exits (INJ +7.7%, SOL +7.62%, ETH +9.30%). This made the strategy appear far worse than it was (71% apparent loss rate) and caused the circuit breaker to incorrectly count profitable trailing-stop exits as hard losses.

**Root cause:** `check_stops_and_tp()` in both `paper_broker.py` and `kraken_client.py` always emitted `exit_reason = "stop_loss"` whenever `current_price <= pos["stop_loss_price"]`, regardless of whether the SL had been raised by the trailing stop mechanism.

**Fix:**
- `src/exchange/paper_broker.py` — In step 4 (full SL/TP check), compute the original hard SL as `entry_price * (1 - stop_loss_pct / 100)`. If trailing is enabled and the current `stop_loss_price` is above this hard floor (by > 0.000001), emit `exit_reason = "trailing_stop"` instead of `"stop_loss"`. Also updated the `audit_logger.log_position_event()` call to emit `"trailing_stop_triggered"` event type.
- `src/exchange/kraken_client.py` — Same logic applied to both the native Kraken order detection path and the price-based fallback path.
- `src/risk/risk_manager.py` — `is_circuit_open()` and `record_stop_loss()` now only count `exit_reason IN ('stop_loss', 'fallback_stop_loss')` as hard losses; `trailing_stop` exits are excluded from the consecutive-stop streak.
- `tests/test_trailing_stop_label.py` — 6 new tests covering: hard SL label when trailing not activated, trailing_stop label after SL raised, profitability assertion, disabled trailing, circuit breaker exclusion, circuit breaker still trips on true hard stops.
