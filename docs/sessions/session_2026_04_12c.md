# Session Notes — 2026-04-12 (Part C)

## Changes

### 1. Fix: qwen3-32b tool_use_failed — apply reasoning_effort: none via Groq API (#223)

**Bug report:** `qwen/qwen3-32b` fails every LLM cycle on Groq with:
```
Error code: 400 - {'error': {'message': "Failed to call a function. Please adjust your prompt.",
'code': 'tool_use_failed', 'failed_generation': ''}}
```
The agent always falls back to `llama-3.3-70b-versatile`; the primary model is never used.

**Root cause:** `qwen/qwen3-32b` is a Groq reasoning model. Thinking mode is **active by default** — the model generates a `<think>…</think>` chain-of-thought block *before* the tool call JSON. Groq's function-call parser cannot handle this ordering and returns `tool_use_failed` with an empty `failed_generation`.

Previous fix (#177) passed `extra_body={"thinking": {"type": "disabled"}}` — this is Anthropic API syntax and Groq returned 400 for **all** models including the fallback llama (reverted in #216). Only `<think>` regex stripping remained, which is defence-in-depth but cannot prevent the generation failure.

**Fix:** Groq exposes `reasoning_effort: "none"` as the correct parameter to disable thinking for qwen3-32b (source: https://console.groq.com/docs/reasoning). Applied via `extra_body={"reasoning_effort": "none"}` in `_call_openai_compat()`, conditionally only when `self._disable_thinking` is `True` AND the model name contains `qwen3`. This ensures the llama fallback is completely unaffected.
