# Session Notes — 5 April 2026 (Part E)

## Changes

### 1. Global Kill Switch
**Bug report / Feature request:** The bot needed a global max daily loss stop-loss to prevent the total portfolio from dropping more than a critical threshold (e.g. 7%).
**Root cause / Motivation:** If multiple pairs hit their individual 5% stop losses simultaneously, the account would crater 15-20% quickly without a macro portfolio fail-safe.
**Fix / Implementation:** Injected `global_max_daily_loss_pct: 7.0` into `config.yaml`. The agent cross-checks this daily in `main.py` against the Net USD value. If hit, the entire portfolio triggers a mass market-sell via CCXT, cancelling all pending limits and shutting down trading loops.

### 2. Backtest Lifecycle Optimization
**Bug report / Feature request:** Repeated backtesting runs were leaving behind old SQLite databases and appending to live standard out logs.
**Root cause / Motivation:** The state file `backtest_paper.db` and the audit logger `backtest_audit.db` were persisting states across runs, which corrupted consecutive baseline calculations.
**Fix / Implementation:** Hardened `test_backtest.py` to immediately delete local backtesting DBs, flush old logs natively, and specifically rotate against `backtest_run.log`.

### 3. Audit Parsing Utility
**Bug report / Feature request:** Needed a clean way to debug why historical 15-min intervals blocked backtest orders.
**Root cause / Motivation:** Logs inside database tables are difficult to visually aggregate quickly during high-iteration testing.
**Fix / Implementation:** Created `scripts/audit_rejections.py`, connecting locally to query the historical database and summarize rejections from quantitative guards, missing LLM volume, or indicator fails.
