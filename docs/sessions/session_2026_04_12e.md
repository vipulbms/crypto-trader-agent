## Changes

### 1. Fix: qwen3-32b tool_use_failed — add reasoning_format=hidden for tool calling (#228)

**Bug report:** `qwen/qwen3-32b` returning HTTP 400 `tool_use_failed` (empty `failed_generation`) on every LLM cycle, causing forced fallback to `llama-3.3-70b-versatile` every call.

**Root cause:** Groq requires `reasoning_format` to be explicitly set to `parsed` or `hidden` when tool calling is enabled. The Groq docs state: _"The format defaults to raw or parsed when JSON mode or tool use are enabled as those modes do not support raw. If reasoning is explicitly set to raw with JSON mode or tool use enabled, we will return a 400 error."_ The existing fix from #223 only passed `reasoning_effort=none` but never set `reasoning_format`. Groq was defaulting to `raw` for `qwen/qwen3-32b` even with reasoning disabled, causing the tool call parser to fail.

**Fix:** Added `reasoning_format: "hidden"` to the `extra_body` dict alongside `reasoning_effort: "none"` in `TradingAgent._call_openai_compat()`. `hidden` returns only the final answer with no reasoning tokens — optimal for tool calling.

**Files changed:**
- `src/agent/trading_agent.py` — `extra_body` now `{"reasoning_effort": "none", "reasoning_format": "hidden"}`
- `tests/test_trading_agent.py` — updated `TestDisableThinking.test_disable_thinking_true_qwen3_passes_reasoning_effort` assertion to expect both keys; updated class docstring to reference #228

**Tests:** 262 passing (8 in `test_trading_agent.py`, all green).
