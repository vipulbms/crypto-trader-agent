### 1. Fix: concurrent HTTP fetches to eliminate cycle stall (#X — no issue)

**Bug report:** When kryptos starts, buy decisions happen quickly. After that, cycles stall for 13–20+ seconds at irregular intervals (approximately 1h, 2h, and 24h after startup).

**Root cause:** `fetch_fear_greed()`, `fetch_btc_dominance()`, and `fetch_cycle_top_indicators()` in `src/analysis/features.py` all use synchronous `requests.get()`. These functions were called sequentially inside `run_cycle()`, an `async` coroutine in `main.py`. When their in-memory caches expire (1h / 2h / 24h respectively), each call blocks the entire asyncio event loop. This also causes `compute_indicators()` to spike from normal 10–15ms to 200–900ms per pair (27 pairs × ~300ms avg = ~8s), because the event loop is starved during the blocking HTTP calls.

**Fix applied (`main.py`):** Replaced sequential synchronous calls with concurrent `asyncio.gather(asyncio.to_thread(...))`:
- Before: `fear_greed_data = fetch_fear_greed(config)` then `btc_dom_data = fetch_btc_dominance(...)` then `cycle_top_data = fetch_cycle_top_indicators(...)` — three sequential blocking calls
- After: All three run concurrently in a thread pool via `asyncio.to_thread()` + `asyncio.gather()` in the non-backtest path. Backtest path unchanged (sequential, cache always warm).
