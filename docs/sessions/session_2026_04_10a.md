# Session Notes — 2026-04-10 (Part A)

## Changes

### 1. RAILS/USD: raise buy_min_score to 7 and halve bearish caution

**Bug report:** Overnight trade analysis showed RAILS contributing 3 stop losses totalling -$21.18, while 5 wins across all pairs yielded only +$6.61 (net -$14.57). RAILS was bought 3× and stopped out each time.

**Root cause:** RAILS had no `buy_min_score` override — it defaulted to 5 (same as ETH/BNB), despite a 75% stop-loss rate. At current prices (~$0.115 vs prior entries ~$0.19–0.21), the pair is down ~40% and still triggering BUY signals at score 5.

**Fix:** `config.yaml`
- `buy_min_score: 7` — requires strong confluence before RAILS fires a BUY (same as INJ)
- `caution_factor_bearish: 0.25` (was 0.40) — cuts max position size to 25% of normal in bearish regime (~$49 on $1,000 portfolio vs $78 previously)

### 2. Unambiguous propose_sell gate in SKILL.md and trading-rules prompt

**Bug report:** The system prompt (`SKILL.md`) listed propose_sell conditions as two alternatives: (a) Signal=SELL + P&L above floor, OR (b) 80% TP proximity + confirmed reversal. This implied the LLM could exit at 1% P&L when Signal=SELL fires, wasting tool calls that get blocked by `validate_sell()`.

**Root cause:** Conditions (a) and (b) were disjunctive. The 80% TP proximity guard is code-enforced by `validate_sell()` but the prompt did not make it a universal prerequisite.

**Fix:** `.claude/skills/trading-rules/SKILL.md`
- Replaced the two-condition disjunction with a single unified gate requiring ALL three: 80% TP proximity (code-enforced), confirmed SELL signal with MACD+RSI reversal, and P&L above profit floor.
- Updated per-pair threshold line to reflect RAILS requiring score 7 and caution 25%.
- Added missing YAML frontmatter (`name: trading-rules`) that caused an IDE diagnostic error.
