### 2. caution_factor Now Code-Enforced (Fix)

**Bug report:** `detect_market_regime()` computes a `caution_factor` (0.5 for bearish, 0.7 for volatile regime) and returns it in `ai_context["regime_data"]`. However, nothing in the codebase read this value — it was computed and discarded. The LLM received the regime text in the prompt, but position size was never actually reduced by code in bearish/volatile markets.

**Root cause:** `caution_factor` was present in `build_ai_context()` output but `main.py` never applied it to `portfolio["max_per_trade"]`.

**Fix (`main.py`, after `build_ai_context()` call):**
```python
caution_factor = ai_context.get("regime_data", {}).get("caution_factor", 1.0)
if caution_factor < 1.0:
    original_max = portfolio["max_per_trade"]
    portfolio["max_per_trade"] = round(original_max * caution_factor, 2)
    logger.info("[REGIME] %s regime — caution_factor=%.2f ...")
```

**Before:** Bearish regime → text warning in prompt, LLM might ignore it, max_per_trade unchanged at e.g. $300.
**After:** Bearish regime → max_per_trade hard-capped at $150 (50% of normal), enforced before the LLM cycle.

### 3. Dynamic TP Now Fires at Order Placement (Fix)

**Bug report:** `compute_dynamic_tp()` calculated ATR/BB-adjusted take-profit percentages and injected them into the LLM prompt as advisory text. But `TradingTools.propose_buy()` called `self._risk.get_take_profit_pct(pair)` — always reading the static config value. Dynamic TP suggestions existed only in the prompt; the actual TP stored in `paper_positions` was always the static value.

**Root cause:** No pipeline connected the computed dynamic TP values to `place_order()`.

**Fix — four files changed:**

1. **`src/analysis/features.py`** — Added `compute_dynamic_tp_values(signals, config) → dict`:
   - Returns `{pair: tp_pct}` for all pairs using `compute_dynamic_tp()` per-pair
   - Returns `{}` if `dynamic_tp.enabled: false`
   - `build_ai_context()` now includes `"dynamic_tp_values"` alongside the existing text block

2. **`src/agent/tools.py`** — Added `_dynamic_tp_values: dict = {}` field + `set_dynamic_tp_values(values)` method:
   - `propose_buy()` now uses: `tp_pct = self._dynamic_tp_values.get(pair) or self._risk.get_take_profit_pct(pair)`
   - Logs `[DYNAMIC_TP] pair using dynamic TP=X%` when override is applied

3. **`src/agent/trading_agent.py`** — Added one line in `run_cycle()`:
   - `self._tools.set_dynamic_tp_values((ai_context or {}).get("dynamic_tp_values", {}))`
   - Called before the LLM decision so dynamic values are ready for any `propose_buy` call

4. **`src/analysis/features.py`** — `build_ai_context()` return dict now includes `"dynamic_tp_values"`.

**Before:** TP at order placement always = static config (e.g. 8% for BTC/USD regardless of ATR).
**After:** TP at order placement = ATR/BB-adjusted value (clamped to 5–20%), falling back to static if dynamic TP is disabled or pair not found.
