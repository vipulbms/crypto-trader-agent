# Session Notes — 5 April 2026 (Part F)

## Changes

### 1. Business Requirements Document

**Bug report / Feature request:** Prepare a formal Business Requirements Document (BRD) for the Kryptos automated trading system.

**Root cause / Motivation:** The project lacked a stakeholder-facing document describing the product scope, functional requirements, and non-functional requirements in a structured format.

**Fix / Implementation:**
- Created `docs/business_requirements.md` covering:
  - Project overview and business context
  - 8 Functional Requirements (FR-01 through FR-08): signal generation, risk management, LLM orchestration, kill switch, min profit floor, audit trail, notifications, paper/live mode
  - 6 Non-Functional Requirements (NFR-01 through NFR-06): performance, reliability, security, maintainability, observability, compliance
  - Bug resolution table mapping reported issues to session fixes
  - Setup and configuration guide

### 2. Detailed Solution Design

**Bug report / Feature request:** Create a comprehensive technical design document for current and future development reference.

**Root cause / Motivation:** The architecture evolved rapidly across multiple sessions without a unified reference document. New contributors or future sessions had no formal spec to read.

**Fix / Implementation:**
- Created `docs/detailed_solution_design.md` with 10 sections:
  1. Conceptual Architecture Diagram (Mermaid flowchart)
  2. Component Responsibilities
  3. Class Diagram (Mermaid)
  4. **Section 3a — LLM Architecture Deep-Dive**: tool-calling loop, SKILL.md injection mechanism, `<think>` block handling (deepseek-r1), fallback model chain, JIT price re-fetch pattern
  5. Data Model & ER Diagram
  6. Exception Management framework
  7. Notification and Alerting architecture
  8. 9 UML Sequence Diagrams (trade lifecycle, kill switch, heartbeat, WebSocket feed, etc.)
  9. Traceability matrix (FR → Component → Test)
  10. Skills System documentation (how `.claude/skills/` works; add-pair, commit, trading-rules skills)
- Included 7 Architecture Decision Records (ADR-001 through ADR-007):
  - ADR-001: Ollama local LLM (vs cloud APIs)
  - ADR-002: SQLite for audit (vs PostgreSQL)
  - ADR-003: WebSocket v2 candle stream (vs REST polling)
  - ADR-004: Post-Only Maker Limit orders
  - ADR-005: Additive confluence scoring (vs hard gate)
  - ADR-006: Code-enforced risk guards (LLM cannot bypass)
  - ADR-007: SKILL.md for trading rules (vs hardcoded prompt)
