### 1. Add entry slippage to PaperBroker.place_order() (#140)

**Bug report / Feature request:** #140 — Entry fills in paper mode filled at exact `current_price` with no slippage. Exit slippage (0.05%) was already applied in `close_position()`, creating an asymmetric friction model.

**Root cause / Motivation:** Every backtest entry was 0.05% too optimistic. On 200 trades/year at 0.05% that compounds to a 10–30% overstatement of annual returns. In real Kraken limit-order trading, even post-only bids on the best bid experience queue position risk and small adverse selection on a 30-minute cycle.

**Fix / Implementation:**
- `src/exchange/paper_broker.py` `place_order()`: changed `fill_price = current_price` → `fill_price = round(current_price * (1 + self._slippage), 8)`. Reuses the existing `self._slippage` field (set from `slippage_pct` constructor param, default 0.05%). Updated the stale comment that incorrectly stated no slippage is paid.
- `config.yaml`: updated `slippage_pct` comment to say "applied on both entry and exit (#140)".
- Round-trip friction model is now: entry slippage (0.05%) + entry fee (0.26%) + exit slippage (0.05%) + exit fee (0.26%) = ~0.62% per trade.
- SL and TP are now anchored to the slipped fill_price (not current_price) — SL/TP distances remain mathematically correct.
- Tests that pass `slippage_pct=0.0` (overdraw guard tests) are unaffected — zero slippage → no change.

**New tests:** `tests/test_entry_slippage.py` (3 tests):
1. `test_fill_price_includes_entry_slippage` — fill_price = current_price × 1.0005
2. `test_sl_tp_anchored_to_slipped_fill_price` — SL/TP compute off slipped price
3. `test_zero_entry_slippage_when_slippage_pct_is_zero` — exact fill at 0%

### 2. Sync LLM prompt "TOP 3" with max_buys_per_cycle=7 (#144)

**Bug report / Feature request:** #144 — `prompts.py` line ~136 told the LLM "Call propose_buy for your TOP 3 picks only" while `config.yaml` has `max_buys_per_cycle: 7` and the risk manager enforces 7. The LLM stopped after 3, wasting valid BUY signals.

**Root cause / Motivation:** The "TOP 3" instruction was set in early development (when position limits were 5 and buys were 3). Fix #130 raised limits to 13 positions / 7 buys per cycle but the prompt was never updated.

**Fix / Implementation (Option A):**
- `src/agent/prompts.py`: added `max_buys_per_cycle: int = 7` parameter to `build_cycle_prompt()`. Changed the hardcoded "TOP 3 picks" to `f"top {max_buys_per_cycle} picks ranked by signal strength"`.
- `src/agent/trading_agent.py`: updated `build_cycle_prompt()` call to pass `max_buys_per_cycle=self._max_buys`. The `self._max_buys` is already read from `config.get("trading", {}).get("max_buys_per_cycle", 2)` in  `TradingAgent.__init__`. Also fixed stale module docstring "default: 2" → "default: 7".
- Config-driven: if `max_buys_per_cycle` changes in `config.yaml`, the prompt updates automatically.
- No new tests (prompt string change only).
