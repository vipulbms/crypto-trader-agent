# Session Notes — 2026-04-12 (Part A)

## Changes

### 1. H4 gate hypothesis analysis — closes #180

**Feature request:** #180 — test whether blocking BUY entries during confirmed 4-hour downtrends (EMA9 < EMA21 AND MACD histogram < 0) improves win rate and P&L.

**Motivation:** The hypothesis was that entries made into a confirmed 4h downtrend were lower-quality trades that dragged down overall win rate. A hard block (or soft penalty) on the `confirmed_down` H4 state would filter these out.

**Implementation:** A new analysis script `scripts/analyse_h4_gate.py` runs two fast-backtest passes (no LLM) over historical candles:

- **Pass 1 (Baseline):** all BUY signals fire; each trade's H4 state at entry is recorded
- **Pass 2 (Gated):** `confirmed_down` BUY entries are downgraded to HOLD before broker execution

Key optimisations in the script:

1. **Vectorised indicator precomputation** (`_precompute_indicators_all`): runs the `ta` library ONCE per pair on the trimmed candle window, building a `{timestamp: indicator_dict}` lookup. Replaces 17–20ms per-step `compute_indicators()` calls with O(1) lookups, reducing total run time from ~147 minutes to ~6 minutes for a 16-month window.
2. **Date-based candle trimming:** each pair's candle history is trimmed to `start_date - 750 candles` before feeding to `ta`, so the DataFrame is small (~10,500 rows vs 26,000) without sacrificing indicator accuracy.
3. **O(n) H4 state precomputation** (`_precompute_h4_states_fast`): incremental EMA updates — avoids the original O(n²) list-slicing per bucket.
4. **`detect_market_regime()` instead of `build_ai_context()`:** avoids the 37ms per-cycle string-building overhead.

**Files changed:**
- `scripts/analyse_h4_gate.py` — new analysis script (not previously in git)
- `README.md` — added H4 gate analysis section with usage examples and last-run verdict

**Result:**

| H4 State | Trades | Win% |
|---|---|---|
| uptrend | 377 | 37% |
| partial_down | 314 | 43% |
| **confirmed_down** | **419** | **44%** |
| TOTAL | 1,110 | 41.4% |

`confirmed_down` entries achieve **43.9% win rate — 2.5pp above overall**. Applying the gate worsens P&L by −$45.79 and drops win rate by −2.1pp.

**Verdict:** Hypothesis NOT supported. The 30m confluence scoring model (`signals.py`) already accounts for macro bearish conditions via RSI, MACD histogram turn, ADX, and per-pair `buy_min_score`. By the time a `confirmed_down` 4h state is present, the 30m model has already filtered down to high-confidence entries — adding a redundant H4 gate removes these good trades.

**Issue #180 closed** — won't implement.
