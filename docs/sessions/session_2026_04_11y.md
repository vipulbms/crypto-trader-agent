# Session Notes — 2026-04-11 (Part Y)

## Changes

### 1. Feat: BTC dominance trend injected into macro regime context (#206)

**Feature request:** Use BTC market-cap dominance trend as a macro rotation signal to better distinguish altcoin risk-on vs BTC/ETH concentration phases.

**Implementation:**

**`src/analysis/features.py`**
- Added `fetch_btc_dominance(config, db_path=None)`:
  - Fetches current BTC dominance from CoinGecko `/api/v3/global`
  - In-memory cache (`_btc_dom_cache`) with `cache_minutes`
  - Optional DB persistence in `agent_state` using key `btc_dom_YYYY-MM-DD`
  - Computes trend (`rising` / `falling` / `flat`) vs `trend_lookback_days` historical reading
  - Returns:
    - `btc_dominance_pct`
    - `btc_dominance_trend`
    - `trend_change_pp`
- Updated `detect_market_regime(..., btc_dominance=None)`:
  - Accepts optional dominance payload
  - Appends macro interpretation to regime summary when trend is rising/falling
  - Adds `btc_dominance_trend` + `btc_dominance_pct` in returned `regime_data`
- Updated `build_ai_context(..., btc_dominance=None)`:
  - Passes dominance data into regime detection
  - Exposes `btc_dominance_trend` and `btc_dominance_pct` in AI context

**`main.py`**
- Cycle-level fetch:
  - Imports and calls `fetch_btc_dominance(config, db_path=_trading_db)` once per cycle
  - Skips fetch during backtest mode
- Passes `btc_dominance=btc_dom_data` into `build_ai_context(...)`

**`config.yaml`**
- Added `regime.btc_dominance` section:
  - `enabled`
  - `url`
  - `cache_minutes`
  - `trend_min_change_pp`
  - `trend_lookback_days`

**Tests**
- Added `tests/test_btc_dominance.py` with 15 test cases:
  - Fetch structure and network failure handling
  - Trend classification: rising / falling / flat
  - In-memory cache behavior
  - Regime return payload includes dominance fields
  - Regime summary overlays for rising/falling cases
  - AI context propagation of dominance fields
- Result: **15/15 passing**
