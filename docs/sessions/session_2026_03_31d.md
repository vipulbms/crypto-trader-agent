# Session Notes — 2026-03-31 (Part D)

## Feature: Ranked Top-2 Multi-Pair LLM Decision Cycle

### Problem
Previously the LLM made **one isolated call per pair** (15 calls per cycle). It could not compare pairs or prioritise capital — it was forced to decide on each pair in isolation, often trading weak signals.

### Change
Replaced the per-pair loop with a **single LLM call per cycle** where the LLM sees all 15 pairs simultaneously, ranks BUY candidates, and selects at most 2 to act on.

### Files Changed

| File | Change |
|---|---|
| `config.yaml` | Added `max_buys_per_cycle: 2` under `trading:` |
| `src/agent/prompts.py` | Rewrote `SYSTEM_PROMPT` with ranked multi-pair decision style; rewrote `build_cycle_prompt()` to add ranked task instructions block at end |
| `src/agent/trading_agent.py` | Replaced `_run_pair_decision()` per-pair loop with `_run_cycle_decision()` single call; added `_resolve_pair()` hallucination guard |

### Architecture

**Before:** `for sig in signals: _run_pair_decision(pair)` → 15 LLM calls
**After:** `_run_cycle_decision(signals)` → 1 LLM call returning N tool calls

**LLM response:** Multiple tool calls in one response (`msg.tool_calls` list).
- `propose_buy`: at most 2 (enforced in prompt AND in code safety net)
- `propose_sell`: any open positions with SELL signal + momentum reversal
- Unactioned pairs: automatic HOLD logged in audit trail

### Key Design Points
- `max_buys_per_cycle: 2` — configurable in config.yaml
- Hard cap in code: if LLM ignores prompt limit, execution skips extra buys with a warning log
- `_resolve_pair()`: validates every LLM-returned pair against the signal list (hallucination guard)
- All 15 pairs get audit entry per cycle (BUY/SELL actioned + HOLD for the rest)
- Stop-loss remains fully autonomous via risk manager — outside this decision flow
- latency_ms=0 for implicit HOLDs (not an LLM call)
