# Session Notes — 2026-04-11 (Part e)

## Changes

### 1. Position sizing cap guard — `max_open_positions` reduced 13 → 5, `compute_position_size` floor, config sanity warning, prompt instruction (#159)

**Bug report:** After 6–7 buys the agent ran out of deployable cash and wasted LLM cycles:
- `max_open_positions: 13` × `base_position_pct: 16%` = 208% of portfolio — arithmetically impossible to fill.
- `compute_position_size()` could return $2–$5 via low-ATR math, polluting the POSITION SIZES block and causing Guard 1 to reject the LLM's proposed amount.

**Root cause:** The config allowed up to 13 simultaneous positions each worth 16% of portfolio, but the total would require 208% of capital. Side effect: suggested sizes in the prompt could be below `min_order_usd`, confusing the LLM.

**Fix — `config.yaml`:**
- `max_open_positions: 13 → 5` (= floor((100-5)/16) = floor(95/16) = 5). Comment updated.

**Fix — `src/analysis/features.py` `compute_position_size()`:**
- Added `min_order = config.get("risk", {}).get("min_order_usd", 20.0)` floor.
- Return changed to `round(max(min(usd_size, max_usd), min_order), 2)`.

**Fix — `src/risk/risk_manager.py` `validate_config()`:**
- Added sanity check: if `max_open_positions × base_position_pct > 100 - min_cash_reserve_pct`, emit `[CONFIG]` WARNING at startup with the correct suggested value (`floor(deployable / base_pct)`).

**Fix — `src/agent/prompts.py` `build_cycle_prompt()`:**
- Added `min_order_usd: float = 20.0` parameter.
- Step 2 instruction now appends: *"Use the suggested size from the POSITION SIZES block. Never pass less than $20 as usd_amount."*

**Fix — `src/agent/trading_agent.py`:**
- `__init__` now stores `self._min_order_usd = config.get("risk", {}).get("min_order_usd", 20.0)`.
- `run_cycle()` passes `min_order_usd=self._min_order_usd` to `build_cycle_prompt()`.

**Fix — `.claude/skills/trading-rules/SKILL.md`:**
- Updated *"currently 13"* → *"currently 5"*.

**Tests added — `tests/test_position_sizing_floor.py`** (8 new tests):
- `TestComputePositionSizeFloor`: 4 tests verifying floor at `min_order_usd`, custom values, and missing config key.
- `TestValidateConfigSanityWarning`: 4 tests verifying warning fires for 13×16%=208%, not for 5×16%=80%, contains suggested value, and boundary case (5×19%=95% ≤ 95%: no warning).

**Test suite:** 180 tests, all passing (was 172).
