## Changes

### 1. #125 — exit_reason=trailing_stop in display/reporting

**Feature request:** Display trailing_stop exits separately from hard stop_loss in the Exit Reasons breakdown, including per-exit-reason P&L totals.

**Root cause / Motivation:** The broker already wrote `trailing_stop` (fixed in #123), but the reporting layer only showed counts without P&L, making it impossible to evaluate whether trailing stops were helping or hurting.

**Fix / Implementation:**
- `src/reports/trade_report.py`: Added `_sum_pnl_by_field()` helper; added `exit_reason_pnl` dict to `get_trade_summary()` return value (sums `pnl_usd` per exit reason).
- `src/cli/display.py`: Updated `print_performance_metrics()` Exit Reasons panel to show both count and total P&L (green/red coloured) per exit reason.
- `docs/how_to_debug.md`: Added `trailing_stop`, `partial_take_profit`, and `backtest_end` rows to the `exit_reason` values table.

### 2. #126 — Minimum position size floor raised to $20

**Feature request:** Raise `min_order_usd` from $5 to $20 to prevent micro-trades that pay disproportionate fees and waste open-position slots.

**Root cause / Motivation:** 2026-04-09 backtest produced positions as small as $5.29, which cannot realistically profit within a 12–20% TP window after fees.

**Fix / Implementation:**
- `config.yaml`: `min_order_usd: 5.0` → `20.0`.
- `src/risk/risk_manager.py`:
  - Added Guard 0.5 immediately after the min-cash-reserve check: if `deployable_cash = available_cash - min_cash_reserve < min_order_usd`, reject with `[RISK] Skipping BUY {pair} — deployable cash $X below min_order_usd $Y`.
  - Fixed hardcoded `capped < 5.0` to `capped < self._min_order_usd` for consistency.
- `tests/test_risk_manager.py`: Added `TestMinOrderUsdFloor` (3 tests):
  - `test_micro_position_rejected_at_20_floor` — $5 proposal rejected at $20 floor.
  - `test_deployable_cash_below_floor_rejected` — deployable $10 < $20 floor rejected.
  - `test_valid_position_above_floor_approved` — $25 proposal approved.

### 3. #127 — Force mark-to-market close at backtest end

**Feature request:** When a backtest finishes, all open positions should be closed at the final candle price so the terminal P&L is fully realised and comparable across runs.

**Root cause / Motivation:** 2026-04-09 backtest ended with 90 open positions valued at entry cost ($6,670), masking the real portfolio value at end of window.

**Fix / Implementation:**
- `src/exchange/paper_broker.py`: Added `force_close_all(prices: dict)` method — iterates all open positions, calls `close_position(id, price, 'backtest_end')` using the supplied end-of-period price per pair.
- `tests/test_backtest.py`: After `asyncio.run(run_agent(...))`, instantiates a fresh `PaperBroker` pointing at the backtest DB, collects `feed.get_latest_price(pair)` for all loaded pairs, calls `broker.force_close_all(last_prices)` and prints the count and total forced-close P&L.
- Import of `PaperBroker` added to `tests/test_backtest.py`.

### 4. #129 — CRITICAL: Overdraw guard in PaperBroker.place_order()

**Bug report:** `place_order()` re-read cash from the DB and subtracted the order cost without verifying the result was non-negative, allowing wallet overdraw.

**Root cause / Motivation:** TOCTOU gap between `validate_buy()` (which checks available cash) and `place_order()` (which performs the deduction). DB contamination or concurrent processes could collapse the guard, as observed in the 2026-04-09 backtest.

**Fix / Implementation:**
- `src/exchange/paper_broker.py`: After computing `new_cash = current_cash - actual_cost - fee_usd`, added:
  ```python
  if new_cash < 0:
      conn.close()
      logger.error("[PAPER] OVERDRAW BLOCKED — would set cash to $%.4f ...", new_cash, ...)
      raise ValueError(f"Insufficient funds: need ${...}, have ${current_cash:.2f}")
  ```
- `tests/test_risk_manager.py`: Added `TestPaperBrokerOverdrawGuard` (2 tests):
  - `test_place_order_raises_on_insufficient_cash` — $10 wallet, $50 order → `ValueError`.
  - `test_place_order_succeeds_within_balance` — $1000 wallet, $50 order → succeeds.
