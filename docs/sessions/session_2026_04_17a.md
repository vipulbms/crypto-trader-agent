### 1. Fix: display.py profit_factor tuple unpacking

**Bug report:** `kryptos.py balance` / `kryptos.py positions` crashes with `TypeError: '<' not supported between instances of 'tuple' and 'float'` when profit factor data is present.

**Root cause:** `get_signal_driver_report()` in `trade_report.py` returns a `(profit_factor, n_trades)` tuple per pair in the `profit_factors` dict. `print_portfolio_summary()` in `src/cli/display.py` calls `pf_by_pair.get(pair_name)` and then directly compares the result against `0.7` and `1.0` thresholds — treating it as a plain float. When the value is a tuple this raises `TypeError`.

**Fix:** Unpack safely before comparison:
```python
# Before
pf = pf_by_pair.get(pair_name)

# After
pf_entry = pf_by_pair.get(pair_name)
pf = pf_entry[0] if isinstance(pf_entry, tuple) else pf_entry
```

**Files changed:** `src/cli/display.py`

Closes #252

### 2. Chore: CI pipeline simplified — remove Copilot review gate

**Motivation:** The GitHub Actions CI had a `copilot-review` job that ran `github/copilot-code-review@v1` on PRs and gated the test job on no critical/high findings. In practice the action added noise and blocked fast feedback. The `test` job already covers correctness via 219 unit tests.

**Change:** Removed `copilot-review` and `create-backlog-issues` jobs. The `test` job now runs unconditionally on every push to `main`, `feature/**`, and `defect/**` branches, and on all PRs to `main` — fulfilling the original intent of issue #181.

**Files changed:** `.github/workflows/ci.yml`

Closes #181
