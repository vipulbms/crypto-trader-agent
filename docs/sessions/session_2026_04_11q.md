# Session Notes — 2026-04-11 (Part Q)

## Changes

### 1. Fix: Per-pair OBV noise threshold — closes #185

**Bug report:** Issue #185 — OBV noise threshold too low for meme/volatile pairs, inflating accumulation signal.

**Root cause:** `_compute_obv_trend()` in `src/analysis/signals.py` used a hardcoded `0.001` (0.1%) floor for OBV change classification. For meme pairs (DOGE, WIF, PEPE, HYPE, JUP), OBV swings ±5–20% per session, so the 0.1% threshold means OBV is classified as "rising" or "falling" on virtually every cycle — never "flat". This awarded the +1 OBV accumulation vote spuriously.

**Fix / Implementation:**

- **`src/analysis/signals.py`**:
  - `_compute_obv_trend(obv_series, period, noise_threshold=0.001)` — added `noise_threshold` parameter; hardcoded `0.001` replaced with the parameter throughout the function body.
  - Updated docstring to document the per-pair override purpose.
  - Call site reads `obv_noise_threshold` from `pair_cfg` → `ind_cfg` → `0.001` fallback, matching the same priority chain as other per-pair overrides.

- **`config.yaml`**:
  - Added `obv_noise_threshold: 0.001` global fallback to `indicators:` section.
  - Added per-pair `obv_noise_threshold` for all 24 active pairs using three tiers:
    - `0.002` (0.2%): BTC, ETH, BNB, SOL — large cap, stable OBV
    - `0.005` (0.5%): XRP, TRX, ADA, LTC, AVAX, SUI, UNI, TON, OP, ARB, RENDER, FET, STX — mid-tier
    - `0.010` (1.0%): INJ, TIA — high-vol but not pure meme
    - `0.020` (2.0%): DOGE, WIF, HYPE, JUP, PEPE — meme/volatile; requires meaningful OBV move

- **`tests/test_obv_signal.py`**:
  - Added 3 new unit tests:
    - `test_obv_noise_threshold_meme_above_floor`: 2.1% OBV rise + threshold=0.02 → "rising"
    - `test_obv_noise_threshold_meme_below_floor`: 0.5% OBV rise + threshold=0.02 → "flat"
    - `test_obv_noise_threshold_large_cap_above_floor`: 0.5% OBV rise + threshold=0.002 → "rising"
  - Total: 11 OBV tests; 202 tests passing overall.
