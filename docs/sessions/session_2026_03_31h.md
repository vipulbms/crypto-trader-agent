### 1. Balance Mismatch — Fee Visibility Fix

**Bug report:** After buying ETH ($140) and LTC ($160) from $1000, remaining cash was $699.22 instead of the expected $700.

**Root cause:** `place_order()` deducts `actual_cost + fee_usd` from cash (e.g. $140.36 total) but the opening trade notification only showed `Invested: $140.00`. The fee was invisible, making cash reconciliation impossible.

**Fix (`src/notifications/notifier.py`):** Extract and display `fee_usd` from the trade dict in the opening trade notification.

**Before:**
```
[PAPER] 🟡 BUY: ETH/USD
Fill: $2021.01 | Vol: 0.069274 | Invested: $140.00
SL: $1919.96 | TP: $2263.53
```

**After:**
```
[PAPER] 🟡 BUY: ETH/USD
Fill: $2021.01 | Vol: 0.069274 | Invested: $140.00 fee: $0.36
SL: $1919.96 | TP: $2263.53
```

### 2. Stale Audit Balance Snapshot Fix

**Bug:** In `main.py::run_cycle()`, `total_usd` and `cash_usd` were captured at the top of the cycle (pre-trade), then used for `audit.log_balance_snapshot()` after trades executed — always recording the pre-trade balance.

**Fix (`main.py`):** Re-fetch balance after `agent.run_cycle()` before writing the snapshot.

```python
# Before — used stale pre-trade values
audit.log_balance_snapshot(total_usd=total_usd, cash_usd=cash_usd, ...)

# After — re-fetch post-trade
post_balance = broker.get_balance()
audit.log_balance_snapshot(
    total_usd=post_balance["total_usd"],
    cash_usd=post_balance["available_cash_usd"],
    ...
)
```

### 3. Stop-Loss Priority — Run Before LLM Decisions

**Bug:** SL/TP checks ran AFTER `run_cycle()`, meaning the LLM could see and act on positions that had already passed their stop-loss price.

**Fix (`main.py`):** Moved `check_stops_and_tp()` block from after `run_cycle()` to before it — SL/TP now runs first in every loop iteration.

```python
while True:
    # Stop-loss / take-profit checks run FIRST — highest priority, before LLM decisions
    if mode == "paper":
        for pair in pairs:
            closed = broker.check_stops_and_tp(pair, current_price, audit)
            ...

    # Then run LLM cycle
    await run_cycle(...)
```

### 5. Premature Sell Prevention — Tighten LLM Exit Rules

**Bug report:** RAILS/USD configured with 20% TP booked only 1.12% profit. DB confirmed `exit_reason = agent_sell` — the LLM called `propose_sell` at $0.1984 (entry $0.1957) instead of waiting for the automatic TP at ~$0.2349.

**Root cause:** The system prompt allowed early exits too loosely — rule 2b only required "close to TP and showing reversal signs", with no minimum profit threshold.

**Fix (`src/agent/prompts.py`):** Tightened both exit rules and added hard guardrails:

| | Before | After |
|---|---|---|
| Rule 2a | Signal=SELL + momentum reversal | Same, AND position P&L > +2% |
| Rule 2b | "Very close to TP and showing reversal" | P&L ≥ 80% of TP target (e.g. TP=20% → need +16%) AND confirmed reversal |
| Override | No floor on sell | Hard ban: do NOT propose_sell below +2% P&L |

**Example blocked by new rules:** RAILS exit at +1.12% (TP=20%) would be blocked — P&L far below 80% × 20% = 16% threshold.
