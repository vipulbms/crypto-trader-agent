# Session Notes — 2026-04-09 (Part B)

## Changes

### 1. Fix #108: Adaptive ATR floor — rolling p25 per-pair injection

**Feature request:** `atr_tp_min_pct` should adapt to current market volatility, not be a fixed static value.

**Motivation:** Static per-pair values (e.g. BTC=0.14%) can't adapt when volatility compresses or expands. Rolling p25 ATR% × scaling_factor gives a floor that tracks market conditions.

**Fix:**
- `config.yaml`: Added `adaptive_atr_floor` section: `enabled: true`, `scaling_factor: 0.8`, `min_cap_pct: 0.10`, `lookback_candles: 400` (global default; per-pair via `adaptive_atr_floor_lookback`)
- `main.py` `run_cycle()`: Computes rolling p25 of `(high - low) / close × 100` per pair over `lookback` candles. Injects as `indicators["adaptive_atr_floor_pct"]`. `signals.py` Hard Blocker 2 reads this first (highest priority in ATR floor chain).
- `tests/test_adaptive_atr_floor.py`: 7 tests covering uniform range, min_cap clamping, lookback windowing, per-pair lookback override, graceful degradation with fewer candles, and signal integration.

### 2. Fix #112: MACD decay threshold normalised to % of price

**Bug:** `exit_timing.macd_decay_threshold: -0.0005` is in absolute histogram units. MACD histogram scales with price — for TRX (price ~$0.20) the threshold fires 0% of the time; for BTC it might fire too aggressively.

**Fix:**
- `config.yaml`: Replaced `macd_decay_threshold: -0.0005` → `macd_decay_threshold_pct: -0.005` (% of price, dimensionless)
- `src/analysis/features.py` `check_exit_timing()`: Computes `macd_hist_pct = macd_hist / price * 100`, compares to `macd_decay_threshold_pct`. Fires consistently regardless of price scale.

### 3. Fix #113: Adaptive BB squeeze — rolling p10 injection

**Feature:** Per-cycle rolling p10 BB width% is injected into indicators as `_rolling_bb_p10_pct`. `compute_dynamic_tp()` already reads this first (priority chain established in session_a).

**Fix:**
- `config.yaml`: Added `adaptive_bb_squeeze` section: `enabled: true`, `lookback_candles: 400`, `percentile: 10`

### 5. Fix #115: Backtest candle timestamps — hold_secs uses candle time

**Bug:** `paper_broker.py` `close_position()` computed `hold_secs` using `now_sgt()` (wall clock). In backtest, this produces a wildly wrong hold duration (2026 system time vs 2025 candle time).

**Fix:**
- `src/exchange/paper_broker.py` `close_position()`: `reference_ts` uses `timestamp_override` (candle time) when provided, falls back to `now_sgt()` in live mode.
- `tests/test_candle_timestamps.py`: 3 tests verifying `opened_at`, `closed_at`, and `hold_secs` all reflect candle time, not wall clock.
