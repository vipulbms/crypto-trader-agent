# Session Notes — 2026-04-19 (Part D)

## Changes

### 1. S13.1.1 — Winsorized EMA-14 volume floor

**Feature request:** Sprint S2 / Story S13.1.1 — replace the noisy rolling-p15 volume floor
with a spike-resistant Winsorized EMA so a single high-volume candle cannot permanently
inflate the floor and block subsequent signals.

**Implementation:**
- `src/analysis/indicators.py`: Before the `return {` block, compute a capped EMA over the
  volume series.  A p95 cap is taken from the last `winsorize_lookback` (100) candles; the
  volume series is clipped at that cap; then an EWM with alpha = 2/(period+1) is applied.
  Result stored as `winsorized_vol_ema` in the returned dict.  When `algorithm=sma` the value
  is `None` (backward-compat path).
- `src/analysis/signals.py` — Hard Blocker 3: Extended the volume veto decision chain.  When
  `qsa.volume_floor.algorithm = winsorized_ema` and `winsorized_vol_ema` is not `None`, this
  is the highest-priority check; the existing `rolling_vol_p15` and `volume_sma_20` paths
  remain as fallbacks in order.
- Config: `qsa.volume_floor.algorithm`, `.period`, `.winsorize_percentile`, `.winsorize_lookback`
  all read from `config.yaml`; default `config.yaml` already contained the `qsa:` section.

### 3. S13.2.1 — Per-cycle OHLCV variance heartbeat (frozen feed detection)

**Feature request:** Sprint S2 / Story S13.2.1 — detect when the WebSocket feed is replaying
stale candles by checking whether the last N OHLCV rows are all identical (zero variance
across all five columns simultaneously).

**Implementation:**
- `src/analysis/indicators.py`: Added `feed_status` computation after the volume floor block.
  Reads `qsa.feed_heartbeat.{enabled, variance_lookback}` (defaults: enabled=True,
  variance_lookback=3).  When enabled and the last `variance_lookback` rows have zero variance
  on every column (`ddof=0`), `feed_status` is set to `"FROZEN"`; otherwise `"OK"`.
  Value added to return dict.
- `src/analysis/signals.py`: After `reasons = []`, reads `indicators["feed_status"]`.  If
  `"FROZEN"`, logs a `[QSA] FEED_FROZEN` warning and returns immediately with
  `signal="HOLD"`, `strength=0.0`, `reasons=["feed_frozen"]`.  Normal scoring is skipped
  entirely for frozen pairs.
