# Session Notes — 2026-04-19 (Part C)

## Changes

### 1. S12.1.1 — Persona config schema in config.yaml (#279)

**Feature request:** Sprint S1 E12 — add configurable risk personas so a single agent binary can run in conservative, medium, or high-risk mode.

**Implementation:**

- **`config.yaml`**: Added `agent:` block with two new keys:
  - `persona: conservative` — which persona profile the agent loads on startup
  - `concurrent_mode: false` — when `true`, DB filenames are suffixed with the persona (enables running multiple agents simultaneously without DB collision)
  Also added full `personas:` block with three profiles (`conservative`, `medium`, `high`), each defining 13 risk knobs: `max_open_positions`, `max_position_pct`, `base_position_pct`, `min_cash_reserve_pct`, `max_buys_per_cycle`, `buy_min_score_override`, `min_profit_floor_pct`, `trailing_stop_enabled`, `trailing_stop_trigger_pct`, `trailing_stop_floor_pct`, `rsi_overbought_override`, `bearish_caution_factor_override`, `prompt_style`.
  Also added `qsa:` (Quantitative Self-Assessment) block with `enabled: false` (placeholder for S13 work).

- **`src/risk/risk_manager.py`**: Extended `validate_config()` to enforce persona block integrity — raises `ConfigError` if `personas:` key is missing, fewer than 3 profiles are present, or any required persona key is absent from any profile's dict.

- **`tests/test_persona_config_loading.py`** (NEW): 12 tests covering valid config, missing personas block, wrong profile count, missing per-profile key, and all 3 profile names validated.

### 2. S12.1.2 — Persona loader and runtime injection (#280)

**Feature request:** Wire the active persona into every trade cycle so risk limits update live per cycle.

**Implementation:**

- **`src/core/cycle_context.py`** (NEW): `CycleContext` dataclass — holds `cycle_id`, `persona`, `persona_config`, `open_positions`, `btc_dominance_trend`. `from_config(config, cycle_id, ...)` class method resolves active persona from `config["agent"]["persona"]` and looks up the full profile dict from `config["personas"][active_persona]`. Eight convenience `@property` accessors expose individual risk limits (`max_open_positions`, `max_position_pct`, etc.).

- **`src/agent/trading_agent.py`**: Added `_current_ctx: Optional[CycleContext]` attribute to `TradingAgent`. `run_cycle()` now accepts `ctx: CycleContext` and stores it as `self._current_ctx`. Propagated to `_run_cycle_decision()`.

- **`src/risk/risk_manager.py`**: Added `apply_persona_config(persona_config: dict)` — reads all 13 keys from the persona dict and hot-patches the 3 live risk limits (`_max_open_positions`, `_max_position_pct`, `_min_profit_floor_pct`). Called from `main.py` after `CycleContext` is built each cycle.

- **`main.py`**: `run_cycle()` now calls `CycleContext.from_config(config, ...)` and immediately calls `risk_manager.apply_persona_config(ctx.persona_config)` so risk limits are always persona-aligned before any trade decision.

- **`tests/test_persona_injection.py`** (NEW): 10 tests covering `CycleContext.from_config()` for all 3 profiles, missing persona falls back to conservative, `apply_persona_config()` hot-patches correctly and is idempotent.

- **`tests/test_position_sizing_floor.py`** (MODIFIED): Added `_MINIMAL_PERSONAS` constant to `_full_config()` helper to fix regression caused by `validate_config()` now requiring a `personas:` block.

### 3. S12.1.3 — Persona persistence and concurrent-mode DB naming (#281)

**Feature request:** Multiple concurrent agent instances must write to isolated DBs; every trade record must be stamped with the active persona for query-time attribution.

**Implementation:**

- **`src/storage/database.py`**:
  - Added `resolve_trading_db(config, mode) -> str` — returns bare filename (`paper_trading.db` / `live_trading.db`) when `agent.concurrent_mode: false`; returns persona-suffixed name (`paper_trading_conservative.db`) when `concurrent_mode: true`. Falls back to `conservative` if `agent.persona` is missing.
  - Added `persona TEXT NOT NULL DEFAULT ''` column to `paper_trades` (PAPER_SCHEMA) and `live_trades` (LIVE_SCHEMA).
  - Added `ALTER TABLE ... ADD COLUMN persona` migration guards in `init_paper_db()` and `init_live_db()` (idempotent — catches `OperationalError` on re-run).
  - Updated `init_all_databases()` to call `resolve_trading_db()` internally instead of hardcoding filename logic.

- **`src/exchange/paper_broker.py`**: Added `persona: str = ""` to `__init__()`, stored as `self._persona`. `close_position()` INSERT into `paper_trades` now includes `persona` as the 16th column value.

- **`src/notifications/notifier.py`**: Added `persona: str = ""` to `__init__()`. Notification prefix is now `[PAPER|CONSERVATIVE] ` when persona provided, `[PAPER] ` in normal mode. Applies to both PAPER and LIVE modes.

- **`main.py`**:
  - Added `resolve_trading_db` to `from src.storage.database import ...` import.
  - `run_agent()` now calls `_trading_db = resolve_trading_db(config, mode)` to resolve DB filename.
  - Computes `_active_persona` and `_concurrent` from `config["agent"]`.
  - Passes `persona=_active_persona if _concurrent else ""` to `Notifier`.
  - Passes `persona=_active_persona` to `PaperBroker`.
  - `run_cycle()` writes `active_persona` to `agent_state` table using `get_connection()` after each `CycleContext` build (try/except with warning log on failure).

- **`tests/test_concurrent_mode_db_naming.py`** (NEW): 19 tests across 4 classes — `TestResolveTradinDb` (8 tests), `TestNotifierPersonaPrefix` (6 tests), `TestPersonaColumnMigration` (3 tests), `TestPaperBrokerPersonaTrades` (2 tests).
