### 1. Fix: volume dead-zone guard uses partial in-progress candle

**Bug report:** `cycle_decisions.log` showed nearly every pair blocked by "Volume dead zone detected" every cycle, leaving capital idle. Example: ETH actual=3.29 vs floor=24.48.

**Root cause:** `compute_indicators()` in `src/analysis/indicators.py` extracted `volume` and `volume_sma_20` from `df["volume"].iloc[-1]` — the current in-progress candle. The WebSocket feed (`websocket_feed.py`) updates the last candle in-place as trades arrive, so `iloc[-1]` accumulates volume in real time and at any arbitrary point during a 15-minute window will have only a fraction of the final completed candle's total volume. Meanwhile, `rolling_volume_p15` is computed in `main.py` from 400 **completed** historical candles. Comparing partial vs completed caused systematic false blocks.

**Fix:** `src/analysis/indicators.py`  
Added `import time`. Inserted a dynamic index block before `return {`:

```python
_candle_interval_secs = config.get("trading", {}).get("candle_interval", 15) * 60
_last_ts = candles[-1].get("timestamp", 0)
_vol_idx = -1 if (_last_ts + _candle_interval_secs) <= time.time() else -2
```

Changed `iloc[-1]` → `iloc[_vol_idx]` for `volume` and `volume_sma_20` only. All other indicators (RSI, MACD, EMA, etc.) remain on `iloc[-1]` — they are correctly computed on the current candle. `signals.py` and `main.py` required no changes.
