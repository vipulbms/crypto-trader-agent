# Session Notes — 5 April 2026 (Part B)

## Changes

### 1. Multi-Indicator Confluence Signal Scoring

**Bug report / Feature request:** Signal logic was either too restrictive (EMA200/EMA50 hard gates blocked all buys) or too loose (candle-counting reversal gate was brittle). Zero BUY signals across 6-month backtest.

**Root cause / Motivation:** Hard gates (single condition = no buy) are fundamentally incompatible with a reversal strategy — by definition, a dip-buy entry happens when price is below the trend EMA. Need multiple weaker signals to combine into a confident score.

**Fix / Implementation:**
- `src/analysis/signals.py` — full rewrite of BUY scoring:
  - Removed all hard gates except two vetoes: RSI ≥ 70 (overbought) and ATR-based TP < profit floor (flat market)
  - 10 contributing signals each add score: RSI oversold (+3), RSI mild oversold (+1), MACD histogram turned positive (+3), MACD histogram positive (+1), MACD line > signal (+1), BB lower touch (+2), EMA9 > EMA21 (+2), price > EMA50 (+1), Fear & Greed fear (+1), Fear & Greed extreme fear (+1)
  - BUY requires ≥ 5 points — needs ~2–3 signals aligned
  - Extracted `_score_sell()` and `_build_result()` as private helpers to avoid duplication across blocker paths
- `src/analysis/indicators.py` — added `macd_histogram_prev` (second-to-last histogram value) to detect turn vs continuation; removed reversal candle counting (consecutive_red/green)
- `main.py` — Fear & Greed index fetched once per cycle and injected into each pair's indicators dict as `fear_greed_index` before `generate_signal()` is called
- `config.yaml` — replaced reversal config keys with new score weight keys: `rsi_mild_oversold_score`, `macd_turn_positive_score`, `ema_short_uptrend_score`, `ema_medium_trend_score`, `fear_greed_fear_score`, `fear_greed_extreme_score`; `buy_min_score` raised to 5; `max_score` raised to 16

### 2. ATR Minimum Profit Floor Gate

**Bug report / Feature request:** In a low-volatility sideways market, ATR shrinks and the dynamic TP target may calculate below the fee break-even point (~0.52% round trip). The agent would enter trades that can never profit.

**Root cause / Motivation:** `compute_dynamic_tp()` uses `ATR × multiplier` — if ATR is tiny, TP < fees.

**Fix / Implementation:**
- `src/analysis/signals.py` — hard veto in `generate_signal()`: if `(atr_multiplier × atr / price) × 100 < min_profit_floor_pct`, signal returns HOLD with `BLOCKED: ATR-based TP X% < Y% floor` reason
- Uses `dynamic_tp.atr_multiplier` (2.0) and `trading.min_profit_floor_pct` (1.0%) from config

### 3. Circuit Breaker — DB-backed, time-windowed

**Bug report / Feature request:** Prevent "revenge trading" — after 3 consecutive stop-losses, pause all new buys for 4 hours.

**Root cause / Motivation:** In-memory state would reset on agent restart, allowing the circuit to be bypassed by restarting. Also, `agent_state` table was unnecessary — trade history already contains the data.

**Fix / Implementation:**
- `src/risk/risk_manager.py`:
  - `is_circuit_open()` queries `paper_trades`/`live_trades` directly with `WHERE closed_at >= <4h ago>` — no separate table needed, survives restarts automatically
  - If the last 3 trades within the 4-hour window are all `exit_reason = 'stop_loss'` → tripped
  - Resume countdown = `most_recent_stop_loss.closed_at + 4h - now`
  - `record_profitable_exit()` is now a no-op — a profitable exit naturally breaks the streak via trade history
  - `RiskManager.__init__` takes `db_path` parameter
  - `validate_buy()` calls `is_circuit_open()` as check #0 before all other checks
- `main.py` — passes correct `db_path` (`paper_trading.db` or `live_trading.db`) to `RiskManager`
- `config.yaml` — `risk.circuit_breaker` block: `enabled: true`, `consecutive_stops: 3`, `pause_hours: 4`
- `tests/test_circuit_breaker.py` — 4 test cases: recent stops trip, old stops don't trip, profit breaks streak, validate_buy blocked
