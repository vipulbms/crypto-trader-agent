# Session Notes — 5 April 2026 (Part B)

## Changes

### 1. Fat Finger and Balance Guards

**Bug report / Feature request:** Resilient feature: Risk: The "Fat Finger" & Balance Guard. Stop buying vast quantities in a flash crash and buffer 2% cash to protect from insufficient fees execution.

**Root cause / Motivation:** If price of an asset drops 90% instantly (flash crash), bot might try to buy a massive amount of "cheap" tokens, hitting order minimum constraints or breaking API limits. Also lack of buffer can break market orders due to fees.

**Fix / Implementation:**
- Added `min_order_usd`, `max_token_volume_per_trade`, and `flash_crash_tolerance_pct` parameters dynamically parsed in `src/risk/risk_manager.py` defaulting config.
- Refactored `validate_buy` in `risk_manager.py` to calculate safe maximums and return strict `False` on extreme anomalous prices compared to macro EMA `baseline_price` or fat-fingered volumes.
- Bound max safe allocation to 98% of available USD.
- Handled edge cases by updating `propose_buy` tool signature to capture current price directly passing it backward as validation parameter.
- Added tests `tests/test_risk_manager.py` to cover anomalies.
