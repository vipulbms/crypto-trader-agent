# Session Notes — 2026-04-01 (Part C)

## Changes

### 1. Backtesting pipeline — signal replay over historical OHLCV

**Bug report / Feature request:** User downloaded 15 pairs of Kraken historical OHLCV data (15-min candles) and asked for a backtesting pipeline that replays signals, executes trades deterministically (no LLM), and generates a P&L report.

**Root cause / Motivation:** No backtest existed; needed to validate that signal logic and broker code produce sensible results before going live.

**Fix / Implementation:**
- `tests/backtest/__init__.py` — package marker
- `tests/backtest/loader.py` — maps display pair names to history JSON files; normalises raw Kraken tick arrays `[time, open, high, low, close, vwap, volume, count]` to candle dicts; documents AVAX filename typo
- `tests/backtest/broker.py` — `BacktestBroker`: pure in-memory PaperBroker equivalent (no SQLite); uses candle high/low for intra-candle SL/TP detection (SL priority); computes hold duration from epoch timestamp delta converted to candle count
- `tests/backtest/runner.py` — slides 221–721 window over candle history; at each step: check SL/TP first, compute indicators, generate signals, buy strongest BUY (strength≥0.5, up to max_buys_per_cycle), sell on SELL if P&L>+2%; force-closes open positions at end
- `tests/backtest/report.py` — formatted text report: portfolio summary, trade log, per-pair breakdown, Sharpe ratio, balance history snapshots
- `tests/test_backtest.py` — entry point; runs backtest, prints report, lists all bugs found

**Bug fixed during build (internal):** `hold_candles` was incorrectly computed as epoch timestamp difference in seconds (e.g. 648000) rather than candle count. Fixed by dividing seconds delta by `15 * 60` to get actual candle count, giving correct hold durations (10–66h range).
