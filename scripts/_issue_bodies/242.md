## Summary
Add a `fetch_news_for_pairs()` function that pulls the latest headlines from public RSS feeds (CoinDesk, Cointelegraph, Google News per-coin query) for a given list of pairs and caches results in memory.

## Motivation
Enable news context to be injected into the LLM cycle prompt (Issue #245) and the `kryptos news` CLI command (Issue #243) without rebuilding the fetch logic twice. Uses free public RSS — no API key, no rate limits.

- [ ] Add `feedparser` to `requirements.txt`
- [ ] Module-level `_news_cache: dict = {}` in `src/analysis/features.py`
- [ ] `_format_news_age(published_at: str) -> str` — returns "30m ago" / "4h ago" / "3d ago"
- [ ] `fetch_news_for_pairs(pairs, config) -> dict[str, list[dict]]`:
  - Returns `{}` immediately if `news.enabled: false`
  - Global sources (CoinDesk, Cointelegraph): fetch once per TTL, filter entries by coin name/symbol appearing in title
  - Per-coin sources (Google News): one fetch per stale pair using `coin_names` map
  - Merges and deduplicates by title across sources; sorts by date desc; slices to `max_headlines`
  - Truncates titles to `headline_max_chars`
  - On fetch failure: logs WARNING per source, skips that source silently (no raise)
  - 30-min in-memory TTL per pair
- [ ] 6 tests in `tests/test_news_fetch.py`:
  - disabled config → returns `{}`
  - successful global fetch + keyword filter → correct grouping by pair
  - successful per-coin Google News fetch → results mapped to pair
  - cache hit (second call within TTL) → skips HTTP calls
  - source fetch failure (exception) → returns partial result gracefully
  - title truncated at `headline_max_chars`

- `feedparser` is MIT-licensed, well-maintained, no heavy dependencies
- No API key required — all sources are public RSS
- Google News RSS has no enforced rate limit in practice; 30-min cache is sufficient
- No DB persistence needed — in-memory cache is fine for 30-min cycles
